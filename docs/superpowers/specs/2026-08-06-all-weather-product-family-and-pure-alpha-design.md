# 全天候实验组合家族与 Pure Alpha 设计

## 文档状态

- 设计日期：2026-08-06
- 当前状态：产品负责人已确认总体方向，可进入文档实施计划
- 适用范围：蜗牛全天候三只实验组合、AlphaLab 与 Pure Alpha 的职责和验证关系
- 证据边界：本文定义研究架构和晋级规则，不表示数据、策略、风险等级或组合表现已经通过历史或前向验证
- 产品状态：当前正式产品数量为零；“低波、中波、高波”均为研究实验组合的暂定名称

## 背景

现有公开材料把“蜗牛全天候·中波”定义为唯一正式展开的母产品概念，低波和高波只保留派生原则；AlphaLab 则被定义为与全天候产品完全隔离的独立研究系统。新的产品方向对这两项决定作出调整：项目将研究三只全天候实验组合，并让 AlphaLab 在保持研究独立的前提下，为三只组合提供经过验证和适配审查的 Alpha 增强能力。

项目不会对外募集或销售这些组合。低波、中波和高波目前是工作名称，最终是否保留，必须由统一口径的回测和前向模拟决定。

现有“系统运转与优化闭环”已经定义问题分类、有限修改、验证和回滚等治理方法，但它目前仍是 V0.1 文档框架。数据接入、历史回测、前向模拟和自动化执行尚未完成，不能把治理设计写成已经运行并闭环的工程系统。

## 核心决定

1. 项目只研究三只实验组合：蜗牛全天候·低波、蜗牛全天候·中波和蜗牛全天候·高波；它们不是已经成立或可销售的金融产品。
2. Pure Alpha 不是第四只产品，而是 AlphaLab 内部的一套复合 Alpha 策略组合。
3. AlphaLab 是研究平台，负责发现、验证、前向观察和淘汰策略；它不直接决定任何产品仓位。
4. 三只实验组合都以全天候核心配置为主体，Pure Alpha 只作为增强模块。高波组合也不能退化成 Pure Alpha 产品。
5. 中波是母组合。低波和高波只能按本文预先规定的派生变量，从中波收紧或有限放宽，不得另建市场判断或验证方法。
6. Pure Alpha 必须先完成独立验证并保留独立模拟净值，之后才能接受产品适配审查。
7. 第一阶段只研究中国股票、ETF、现金和多头仓位，不使用杠杆、融券、期货或期权。
8. 风险等级和任何数值阈值只能在数据契约、回测与压力测试完成后确定，当前不作收益、波动或回撤承诺。

## 术语与关系

### AlphaLab

AlphaLab 的目标职责是承担策略研究与治理。实施后，它应保存策略编号、假设、数据契约、实验版本、回测结果、前向记录、反证、失效条件和淘汰决定。

### Alpha 子策略

Pure Alpha 第一阶段允许研究四类子策略：

- 选股；
- 市场择时；
- 行业、风格或资产轮动；
- 事件驱动。

每条子策略必须独立编号、独立验证和独立归因。某一类没有合格策略时可以保持空缺，不为追求形式完整而补入未经验证的规则。

### Pure Alpha

Pure Alpha 是由已经晋级的 Alpha 子策略组成的复合策略组合。实施后，它应负责处理信号冲突、重复暴露、行业和风格集中、资金竞争、流动性、换手成本、现金仓位与组合风险，并长期保留独立的模拟净值和归因记录。

“有什么有效信号就做什么”在本设计中表示允许研究多类机会，不表示跳过策略规范、验证门槛或组合风险约束。

Pure Alpha 分为两个层次：

- `Pure Alpha Reference`：统一候选池形成的研究影子组合，保留一条独立参考净值和完整归因；
- `Low / Mid / High Alpha Sleeve`：经过产品适配后形成的低波、中波和高波专属增强子组合，各自保留版本、净值和归因。

产品不能绕过 Pure Alpha 组合治理直接挑选一条历史表现漂亮的子策略。产品专属 sleeve 可以采用不同的合格策略子集，但所有成员都必须先进入同一候选池，并通过冲突、暴露、资金和成本审查。

### 全天候实验组合家族

三只组合共享同一套宏观环境判断、资产角色、市场数据、风险闸门、AlphaLab 证据和回测口径。它们的主要差异来自产品风险预算，而不是来自三套不同的市场判断。

本文中的“产品层”“产品适配”和“产品风险预算”是目标职责名称，不表示当前存在正式产品或已经运行的产品系统。

## 总体架构

```text
AlphaLab
  ├─ 选股策略
  ├─ 择时策略
  ├─ 轮动策略
  └─ 事件驱动策略
          ↓
独立验证与前向模拟
          ↓
Pure Alpha Reference 影子组合
          ↓
组合前向观察
          ↓
产品适配审查 → Mid Alpha Sleeve
          ↓
全天候中波母组合联合验证
          ↓
中波风险结构形成证据后解锁派生
      ↙                    ↘
低波产品适配审查          高波产品适配审查
      ↓                    ↓
Low Alpha Sleeve         High Alpha Sleeve
      ↓                    ↓
低波派生组合             高波派生组合
```

研究和产品之间是受控的单向关系：AlphaLab 可以向产品适配环节提交已经验证的候选能力，产品风险预算层可以接受、限制或拒绝候选能力；产品近期表现不能反向改写已经冻结的策略版本。

共同风险边界、产品风险预算和执行风险闸门高于任何 Alpha 信号。Alpha 只能在剩余风险预算内表达；择时、轮动或事件信号不能反向覆盖全天候风控。

## 分层职责

### AlphaLab 的职责

- 提出可证伪的策略假设；
- 定义研究对象、点时数据和交易约束；
- 实施历史验证与独立前向模拟；
- 保存成功、失败和被淘汰的实验；
- 管理策略版本、暂停、恢复、降级和淘汰；
- 向 Pure Alpha 提交已经满足晋级条件的子策略。

AlphaLab 不输出产品最终仓位，不拥有产品风险预算，也不能因为某只组合近期表现不佳而临时改变冻结规则。

### Pure Alpha 的职责

- 组合已经晋级的子策略；
- 识别重复的市场、行业和风格暴露；
- 解决信号冲突和资金竞争；
- 控制组合集中度、流动性与换手成本；
- 保存独立净值以及选股、择时、轮动、事件、市场 Beta、成本和残差归因；
- 接受组合层前向观察，不以子策略历史收益的简单相加代替组合验证。

### 产品适配审查的职责

- 判断一条子策略或 Pure Alpha 组合是否适合低波、中波或高波；
- 评估加入后的边际收益、边际波动、尾部风险、集中度和回撤修复时间；
- 检查 Alpha 是否在全天候核心最需要保护时同步失效；
- 形成允许使用、限制使用、继续观察或拒绝接入的记录；
- 为产品风险预算层提供证据，不替代产品最终决定。

### 全天候产品风险预算层的职责

- 决定全天候核心和 Alpha 增强模块各自可以承担多少风险；
- 在宏观边界、市场状态和风险闸门约束下形成产品限制；
- 在条件收紧时降低或关闭 Alpha 增强仓；
- 预先定义 Alpha 增强仓的限制、关闭和恢复条件；
- 保证高波组合仍保留全天候核心，不通过取消风控获得更高风险；
- 允许 Alpha 增强预算为零，不为维持产品叙事而强行配置策略。

### 决策权与输出

| 决策 | 负责层 | 输出与权限边界 |
|---|---|---|
| 子策略是否进入候选池 | AlphaLab 策略评审 | 决定晋级、观察、返回、暂停或淘汰，不决定产品仓位 |
| Pure Alpha Reference 的成员和组合器版本 | Pure Alpha 组合评审 | 决定研究影子组合，不决定产品总风险 |
| Low / Mid / High Alpha Sleeve 的成员和版本 | 产品适配评审 | 批准对应 sleeve 的成员和版本，不拥有产品总风险预算 |
| 全天候核心与 Alpha 的最终风险预算 | 产品风险预算评审 | 在上游共同边界内决定 Alpha 预算，并可将不满足产品约束的 sleeve 退回适配评审 |
| 模拟目标持仓与执行状态 | 执行层 | 只能在最终预算和风险闸门内生成模拟动作，不改写上游规则 |
| 风险闸门触发后的限制、关闭或恢复 | 执行层风险闸门 | 只执行产品风险预算层预设的条件，优先于任何 Alpha 信号；不得自行修改准入或恢复规则 |

## 策略生命周期与晋级门槛

### 1. 策略想法

记录机会来源、适用环境、作用机制、交易对象、可能为 Alpha 付费的一方以及可以否定假设的证据。近期表现或事后相关性不能单独构成策略假设。

### 2. 策略规范

在查看最终结果前冻结研究范围、股票或 ETF 池、信号、调仓频率、成本假设、比较基准、失效条件和主要验证判据。范围变化必须产生新版本。

### 3. 历史验证

检查点时数据、幸存者偏差、未来信息、样本内外、Walk-forward、交易成本、可交易性、参数稳定性和多重测试。累计收益高不能自动晋级。

### 4. 独立前向模拟

按照真实时间记录信号、模拟订单、成交或未成交、异常和规则版本。未完成独立前向模拟的子策略不能进入 Pure Alpha 正式候选池。

### 5. Pure Alpha 影子组合

将已经晋级的子策略放入统一组合，检查信号冲突、风险叠加、重复暴露、流动性、换手与组合后的增量价值。单条策略有效不代表组合后仍然有效。

### 6. 组合前向观察

Pure Alpha 继续按真实时序保存组合信号、模拟持仓、成本和归因。组合规则变化需要新版本和新的观察记录。

### 7. 产品适配验证

分别比较全天候核心组合与“全天候核心组合加对应的 Low / Mid / High Alpha Sleeve”，确认收益是否来自真实增量而非更多市场 Beta，并检查尾部损失、分散效果、成本和失效相关性。Pure Alpha Reference 只保留研究侧对照净值，不直接成为实验组合持仓。

### 8. 全天候实验组合

候选增强能力先进入中波母组合的联合回测与前向模拟。中波风险结构形成证据后，再按统一派生规则生成低波和高波。进入实验组合不等于获得真实资金、实盘资格或产品发行资格。

每一阶段只能形成晋级、继续观察、返回修改、暂停或淘汰等可追溯决定。单次盈利不能自动晋级，单次亏损也不能自动淘汰。

## 三只实验组合的派生关系

### 共同约束

三只组合共享：

- 宏观共同风险边界；
- 资产桶定义和市场数据；
- 市场信号与失败状态；
- 执行风险闸门；
- AlphaLab 候选策略的同一证据版本；
- 数据、交易成本、回测和归因口径。

三只组合不能根据各自表现选择不同的历史数据、成本假设或市场解释。

### 中波母组合

中波首先形成全天候核心配置、标准产品风险预算、标准 Alpha 增强预算、再平衡规则、风险闸门以及完整的历史和前向记录。它是派生基准；在验证完成前，“中波”只表示母组合工作名称。

### 低波派生组合

低波只能通过收紧中波约束形成，包括降低整体风险预算、降低高波动资产容纳空间、降低 Alpha 增强预算、缩小可采用的 Alpha 策略集合，以及更早进入收敛或防守。具体比例和阈值由后续验证决定。

### 高波派生组合

高波只能在中波基础上有限放宽整体风险预算、成长资产和 Alpha 增强模块的容纳空间。它仍受共同风险边界、集中度上限和风险闸门约束，不使用杠杆，也不能把全天候核心降为无实质作用的名义仓位。

### Alpha 策略适配

三只组合使用同一个已验证候选池，但不必机械持有同一组 Alpha 策略或按固定倍数缩放。每条策略必须分别通过低波、中波或高波适配审查。没有通过审查的策略不能因其独立历史收益较高而进入产品组合。

派生过程中允许变化的只有：总风险预算、资产风险上限、Alpha 风险上限、合格策略准入子集，以及经过统一设计并预先登记的防守触发阈值。不得变化的包括：历史数据、点时语义、宏观状态定义、共同风险边界、风险闸门优先级、交易成本、样本划分和验证口径。

## 回测、风险分类与命名

### 统一比较口径

三只组合必须使用相同的历史区间、点时数据、交易日历、可交易性规则、手续费、滑点、调仓假设、样本划分、市场环境划分、基准和无风险收益口径。

### 风险评价维度

风险分类至少同时检查：

- 年化波动率；
- 最大回撤；
- 尾部损失和最差滚动区间；
- 回撤修复时间；
- 下行波动和下跌市场表现；
- 权益、行业、风格和 Alpha 风险贡献；
- 换手率、交易成本和流动性；
- 不同增长、通胀、流动性和市场压力环境下的稳定性。

收益率、夏普和 Sortino 用于评价组合质量，但不能单独决定风险等级。

### Pure Alpha 增量对照

每只实验组合至少保留“全天候核心”和“全天候核心加对应 Alpha Sleeve”两组结果。Pure Alpha Reference 同时保留研究侧独立净值和子策略归因，用于区分真实 Alpha、市场 Beta、风格暴露、成本和残差；它不直接作为任何实验组合的持仓。

### 最终命名条件

只有当样本外、滚动窗口、多种市场环境和独立前向模拟中都相对稳定地呈现“低波风险低于中波、中波风险低于高波”，才正式保留三个风险名称。

若排序不稳定，先检查风险预算和策略适配，再重新派生组合；仍无法形成稳定层级时，改用中性编号或风险预算编号。不得通过挑选有利区间、调整比较口径或事后解释保留名称。

数值风险目标、阈值和代表产品不在本设计中决定。它们必须在数据契约完成并另行批准回测范围后，通过预先登记的验证规则产生。预登记至少需要明确风险排序主指标和辅助指标、多指标冲突处理、容忍度、最少滚动窗口、市场环境覆盖、最短独立前向观察期及排序失败条件。没有完成预登记时，不执行正式命名判断。

## 失败处理与治理

- 数据不可重建、点时语义不清或存在未来信息时，停止策略验证，不用插值或事后数据掩盖问题。
- 子策略失效时，先区分数据、判断、规则、执行、表达和市场随机波动，不直接改参数。
- Pure Alpha 组合表现异常时，分别检查子策略、共同暴露、组合器和成本，不能只看合计净值。
- 产品排序倒挂时，视为产品派生或适配问题，不把名称当作必须满足的结论。
- 风险闸门触发时，产品风险预算层预设的条件可以限制、关闭或恢复 Alpha 增强仓，执行层只负责按条件执行；AlphaLab 继续保存研究记录，但不能绕过产品限制。
- 所有修改保存原问题、证据、版本、验证条件、保留条件和回滚条件。

本设计允许：

- 定义三只实验组合及其关系；

- 设计策略生命周期、验证门槛和文档结构；
- 在后续获批阶段使用历史回测与前向模拟验证研究假设。

本设计不授权：

- 对外募集、销售或宣传金融产品；
- 使用真实资金或连接券商自动交易；
- 使用杠杆、融券、期货或期权；
- 在没有数据契约和预登记验证规则时确定具体参数；
