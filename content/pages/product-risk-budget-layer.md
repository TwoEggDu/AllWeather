## 1. 这篇文章在系统中的位置

产品风险预算层是蜗牛全天候六层系统的第四层，位于[资产层](/asset-layer/)、[信号层](/signal-layer/)之后，[执行层](/execution-layer/)之前。

前三层回答共同环境是什么、每类资产负责什么、市场状态怎样；本层回答：

> 在这些共同判断和某款产品自身风险偏好之下，这款产品最多允许承担怎样的风险，六个资产桶可以在什么约束结构内被使用？

本层形成产品约束，不是资产配置答案，更不是交易指令。

## 2. 为什么需要单独的一层

同一宏观环境下，不同风险偏好的产品可以有不同风险预算，但不能各自创造宏观事实。市场信号也不能直接交易：信号描述资产桶的市场状态，本层才检查这些状态能否在共同边界和产品偏好内被使用。

若省略本层，宏观文章容易直接写权重，强信号可能突破共同风险上限，执行层也可能临时重新解释产品目标。独立的产品风险预算层让“共同判断、产品约束、实际执行”分别留下责任和证据。

## 3. 本层要回答什么问题

1. 产品总体风险预算处于可使用、维持、收紧、显著收紧还是未知；
2. 六个资产桶的使用资格、约束方向和增加风险权限分别处于什么状态；
3. 已批准的上下限规则结构应保持、收紧，还是等待证据；
4. 当前是否允许在既定边界内增加风险，是否要求减少可承担风险；
5. 哪些冲突、缺失或失效条件必须交给执行层和复盘层。

这些词描述约束方向，不代表已经存在数值参数，也不表示执行层必须产生动作。

## 4. 输入

| 输入 | 最少内容 | 不能怎样使用 |
|---|---|---|
| 共同宏观边界 | 开放、中性、收敛、防守或未知；证据、未知和更新时间 | 开放不能解释为必须增加风险，也不能在本层改写宏观状态 |
| 资产角色 | 六个资产桶的功能、风险、使用边界和版本 | 不能因短期强弱增加资产桶或改变长期角色 |
| 市场信号 | 各桶趋势、相对强弱、波动与回撤风险，以及缺失和冲突 | 单个强信号不能突破宏观上限 |
| 产品风险偏好 | 当前仅为中波母产品的相对风险偏好、资金期限和流动性假设 | “中等”不能冒充目标波动、权益比例或收益目标 |
| 现行约束版本 | 上一次评审通过的边界、允许范围、失效条件和生效时间 | 不能用当前持仓反推产品目标 |

输入必须说明来源版本、形成时间和完整性。需要点时数据的输入还要记录真实可得时间。

## 5. 处理过程

本层先检查输入是否齐全、版本是否一致、未知项是否显式记录；缺失不能默认填成中性。

随后应用单向约束：宏观边界规定共同上限，资产层规定资产为何存在，信号只能在前两项边界内支持使用、限制使用或继续观察，中波产品偏好只能在共同上限内形成自身约束。

若宏观与信号冲突，强信号不能突破宏观上限；如果信号支持收紧，本层可以形成更窄的允许范围；如果信号支持扩张，也只能写“在既定边界内允许”，不能要求增加风险。

## 6. 共同风险来源不能重复计算

六个资产桶不天然等于六份独立风险。多个桶可能同时受到增长、利率、流动性、估值或同一市场因子驱动。资产层声明结构性重叠；本层负责把这些重叠纳入组合层面的集中度和分散约束判断，不能只按名称判断已经分散。

V0.1 只记录风险来源、重叠和冲突，并作出定性的集中度约束判断，不计算相关性或风险贡献，也不采用旧文中的相关性窗口或分配比例。这项判断不是第四类市场信号，不能在规则未定义时直接触发动作。

组合集中度约束只使用以下最小状态：

| 状态 | 含义 | 下游处理边界 |
|---|---|---|
| 无新增约束 | 没有足够证据要求在现行产品约束之外继续收紧 | 不代表已经实现定量分散，也不要求增加风险 |
| 收紧 | 结构性重叠或共同风险来源要求缩小部分允许范围 | 不给出比例或具体动作 |
| 显著收紧 | 严重集中或多项冲突要求明显降低可承担风险 | 不等于清仓或执行暂停 |
| 未知 | 信息不足、口径待验证或无法判断 | 不得解释为无集中风险 |
| 无效 | 输入版本冲突或规则无法形成合法约束 | 执行层只能阻塞、谨慎或暂停，不能补造约束 |

## 7. 总体风险预算怎样表达

| 状态 | 含义 | 不代表什么 |
|---|---|---|
| 可使用 | 共同边界没有要求额外收紧，产品可以在已批准约束内使用风险预算 | 不要求增加风险，也不代表满额使用 |
| 维持 | 没有足够证据改变现行约束 | 不表示市场没有变化，也不等于实际仓位不变 |
| 收紧 | 不利证据或集中风险要求缩小部分允许范围 | 不给出缩小比例或交易顺序 |
| 显著收紧 | 防守边界或严重冲突要求明显降低可承担风险上限 | 不等于清仓、暂停或指定资产动作 |
| 未知 | 输入缺失、冲突无法解释或规则未验证 | 不能自动当成中性，也不能据此扩大风险 |

## 8. 每个资产桶的允许范围

每个资产桶依次检查：角色是否仍在六桶定义内，宏观边界是否限制其风险使用，三类信号是支持、反对、冲突还是未知，以及它是否与其他桶共享过多风险来源。检查结果拆成三个字段，不能合称为一个含义模糊的“资产桶状态”：

- **使用资格**：已批准 / 未批准 / 未知；
- **约束方向**：保持 / 收紧 / 显著收紧 / 未知；
- **增加风险权限**：既定边界内允许 / 不允许 / 需要更多证据 / 未知。

本层只给允许范围的结构和方向。具体下限、上限、风险贡献或资金比例必须进入未来带版本的参数表，并经过历史模拟和前向观察。

## 9. 上下限规则结构

| 字段 | V0.1 可用表达 |
|---|---|
| 使用资格 | 已批准 / 未批准 / 未知 |
| 约束方向 | 保持 / 收紧 / 显著收紧 / 未知 |
| 增加风险权限 | 既定边界内允许 / 不允许 / 需要更多证据 / 未知 |
| 减少风险要求 | 无新增要求 / 需要收紧 / 需要显著收紧 / 未知 |
| 本轮约束决定 | 保持约束不变 / 更新约束 / 无法形成有效约束 |

若不同约束导致下限可能高于上限，或资产角色与产品偏好无法同时满足，本层必须输出约束冲突，不能强行给出结果。

## 10. 增加、减少和保持分别指什么

- “允许增加风险”只表示执行层在其他条件满足时，可以在既定边界内形成模拟候选，不是加仓指令；
- “要求减少可承担风险”表示产品允许范围需要收紧，具体何时和怎样模拟由执行层决定；
- “保持不动”在本层准确写作“保持产品约束不变”，不等于保持实际仓位不动；
- 模拟增减、保持仓位、谨慎、暂停和恢复都属于执行层。

因此，产品约束保持不变时，执行层仍可能因执行条件异常进入谨慎或暂停。

## 12. 中波母产品与本层怎样分工

本页定义所有产品实例共同遵守的第四层规范；[蜗牛全天候·中波概念卡](/middle-risk-product/)定义当前唯一母产品的目标、相对风险偏好、资产范围和成熟度。

| 层级规范 | 中波概念卡 |
|---|---|
| 定义所有产品共用的输入、处理、约束卡和失败状态 | 定义当前母产品为什么存在、面向什么相对风险偏好 |
| 不拥有某个产品的目标参数 | 提供中波产品偏好作为本层输入 |
| 未来可以由不同产品实例调用 | 当前不包含已验证的完整产品规则 |

## 13. 低波和高波只从中波派生

低波和高波不拥有独立的宏观判断、资产桶或市场信号。低波未来只能在中波经过验证的结构上进一步收紧风险预算和资产上限；高波只能适度放宽中波约束，但始终受同一宏观边界、资产角色和风险闸门约束。

当前不为两者创建独立页面、权重、目标波动、收益目标或执行规则。在中波尚未验证前，“收紧”和“放宽”只有相对含义。

## 14. 失败、未知和冲突状态

宏观边界缺失或过期、资产角色版本不一致、市场信号不可复查、产品风险偏好未批准、现行约束版本无法找到、多项约束无法同时满足时，本层输出未知或无效约束。

合法失败状态包括 `unknown`、`invalid_input`、`constraint_conflict`、`rule_not_validated` 和 `no_update`。`no_update` 不等于执行暂停；执行层仍需依据自身规则决定保持不动、谨慎或暂停。

## 15. 本层明确不能做什么

- 创造、修正或覆盖宏观判断；
- 改变六个资产桶角色，或因热点增加资产桶；
- 让强信号突破共同宏观边界；
- 指定指数、基金、ETF、期货或具体工具；
- 写入未经验证的权重、上下限、目标波动、最大回撤、风险贡献、频率或阈值；
- 输出买卖、加减仓、清仓、申赎、暂停或恢复指令；
- 根据当前持仓、一次盈亏或未来数据反向修改产品目标；
- 输入缺失时用默认值制造完整结果。

## 16. 当前成熟度与待验证事项

```text
层级职责定义（当前）
  → 中波规则草案
  → 参数与数据契约
  → 历史模拟
  → 前向观察
  → 稳定公开
```

待验证内容包括总体风险度量、六桶基础范围、宏观边界到中波约束的映射、信号怎样支持收紧或恢复、共同风险来源、状态切换条件、参数存储、复查条件、成本和代表工具，以及合作伙伴能否区分“保持约束不变”和“保持实际仓位不动”。
