## 1. 这篇文章在系统中的位置

宏观层是蜗牛全天候六层投资系统的第一层。它面对的是所有产品共同经历的市场环境，而不是某一款产品的偏好。

增长、通胀与价格、流动性与信用、政策、全球外部环境和事件风险，是宏观层内部的六个证据模块，不是六层投资系统中的另外六层：

```text
六层投资系统
1. 宏观层
   ├─ 增长
   ├─ 通胀与价格
   ├─ 流动性与信用
   ├─ 政策
   ├─ 全球外部环境
   └─ 事件风险
2. 资产层 → 3. 信号层 → 4. 产品风险预算层 → 5. 执行层 → 6. 复盘层
```

它接收点时可核验的宏观事实和事件信息，形成两项输出：

1. 一份对共同环境的描述，包括六个模块的状态、变化方向、证据和未知项；
2. 一项共同风险边界，供产品风险预算层决定某款产品最多可以承担多少风险。

这里的“共同”很重要：高波、中波和低波产品可以有不同风险预算，但不能各自创造一套宏观事实。

## 2. 它要回答什么问题

宏观层只回答五类系统问题：

- 当前共同环境由哪些当时可得、能够复核的事实构成；
- 增长、价格、流动性与信用、政策、全球外部环境、事件风险各自处于什么状态；
- 状态相对上次记录在改善、恶化、稳定、分化，还是无法判断；
- 六个模块的支持证据、反对证据和未知项共同要求怎样的风险上限；
- 哪些新事实会推翻判断，以及何时必须复查。

宏观层不回答具体产品买什么、买多少或什么时候交易。

## 3. 为什么需要这个模块

如果没有独立的宏观层，单条新闻、单个指标或一次市场涨跌很容易同时改变环境判断、资产观点和产品动作。这样既无法知道真正改变了什么，也无法复查错误来自数据、判断、规则还是执行。

宏观层把“事实如何变化”与“产品如何行动”拆开。它允许系统在证据不足时正式记录未知，也允许多个模块相互矛盾，而不是为了给出动作强行制造一个确定结论。

## 4. 候选观察信息

宏观层固定使用六个模块，不在旁边继续增加单指标主线：

| 模块 | 系统问题 | 候选信息 | 本层边界 |
|---|---|---|---|
| 中国增长 | 经济动能在改善、走弱还是分化？ | 生产、需求、就业、地产和外需信息 | 不把一个景气指标当成增长结论 |
| 中国通胀与价格 | 价格压力来自哪里，方向与持续性如何？ | 居民价格、工业价格、工资、商品和服务价格 | 不从一个价格指标直接推导资产方向 |
| 中国流动性与信用 | 银行间资金、实体信用和市场融资条件在放松、收紧还是传导不畅？ | 货币市场、社会融资、银行信贷和融资压力信息 | 不把政策意图等同于实际流动性结果 |
| 中国政策 | 政策处于表态、发布、执行还是传导阶段？ | 货币、财政、地产、产业和资本市场政策 | 表态本身不能证明政策已经产生效果 |
| 全球外部环境 | 外部增长、利率、汇率、商品和风险压力怎样约束中国共同环境？ | 全球增长、主要利率、美元、商品和跨市场压力 | 不建立独立的美联储、美元或油价交易主线 |
| 日历与事件风险 | 哪些计划事件或突发事件可能改变证据质量和风险上限？ | 数据日历、政策日历、地缘、金融稳定和制度事件 | 一条新闻不能直接改变长期判断或产生交易 |

这些只是候选信息类别，不是已批准的指标清单。具体字段、口径、来源、发布时间和版本需要在数据契约中逐项验证。

## 5. 数据和证据怎样记录

每个模块使用同一张状态卡。状态卡必须区分数据描述的时期、数据何时真实发布，以及判断何时更新：

```yaml
module: "模块名称"
status: "unknown"
direction: "unknown"
data_as_of: "unknown"
available_at: "unknown"
last_updated_at: "unknown"
supporting_evidence: []
contrary_evidence: []
unknowns: []
confidence: "unknown"
invalidation_conditions: []
next_review_at: "unknown"
downstream_output: "none"
```

- `data_as_of`：数据描述到哪个时期；
- `available_at`：这条数据或信息在现实中何时可被使用；
- `last_updated_at`：研究判断何时被更新；
- 来源、口径、版本或修正无法确认时，该证据只能进入未知项，不能支撑确定状态。

## 6. 支持证据

支持证据必须与模块问题直接相关，并满足三个条件：来源可追溯、当时真实可得、变化方向能够解释。记录时应写清事实、时间、来源和它支持哪一部分判断。

证据数量不是强度。一组同源、同滞后或重复表达的信息不能因为条目多就获得更高地位。

## 7. 反对证据

每个状态都必须主动寻找反对证据和替代解释。例如，总量改善可能被少数项目推动，价格变化可能来自供给而非需求，流动性宽松可能没有进入实体信用。

反对证据不是附注。若它足以改变状态、方向或置信度，必须同步修改状态卡；若暂时无法解释，则进入未知项并设置复查条件。

## 8. 未知项

以下情况应正式记录为未知：数据尚未发布、来源或口径未核验、修正版本未确认、模块内部证据冲突、因果路径仍是推测，或事件影响尚未传导。

“未知”不是缺陷，也不能被默认解释为中性。它说明当前证据不足以支持更强的系统判断。

## 9. 模块状态怎样表达

六个模块先各自表达状态，再形成一项共同风险边界。宏观层当前只允许以下四种边界语言：

| 边界 | 系统含义 | 不代表什么 |
|---|---|---|
| 开放 | 共同环境没有要求产品额外收缩风险，产品可在自身规则内使用风险预算 | 不代表必须增加风险或买入某类资产 |
| 中性 | 证据均衡、方向不清或模块分歧尚不足以要求统一收缩 | 不代表所有资产权重相同，也不把未知自动当中性 |
| 收敛 | 不利证据、不确定性或模块冲突上升，共同风险上限需要收紧 | 不等于执行暂停，也不直接给出减仓比例 |
| 防守 | 共同环境要求产品显著降低可承担风险的上限 | 不等于清仓，不指定任何具体资产动作 |

六模块如何汇总、冲突怎样处理、何时切换边界仍待验证。本阶段不建立评分、模块权重、阈值或自动切换公式。

置信度只描述证据完整度和判断稳定性，不是第二套交易信号，不能自动放大或缩小任何产品风险。

## 10. 模块向下游输出什么

宏观层向资产层和产品风险预算层提供：

1. 六张完整状态卡；
2. 一段共同环境描述；
3. 一项开放、中性、收敛或防守的共同风险边界；
4. 主要反对证据、未知项和置信度；
5. 失效条件与下次复查日期。

此外，本层只允许两项经过限权的定性输出：

- **权益风险约束方向**：共同环境是否要求权益类风险承载能力受到额外收紧。它不包含比例、产品差异或动作；实际产品上限由产品风险预算层形成。
- **环境功能需求**：当前环境要求资产层重点复核哪些功能，例如流动性缓冲、下行缓冲、购买力保护或增长参与。它不映射具体资产，也不表示某类资产应当占优。

```yaml
macro_layer_state:
  environment_state: "unknown"
  direction: "unknown"
  shared_risk_boundary: "unknown"
  equity_risk_constraint_direction: "unknown"
  environmental_function_needs: []
  module_states: []
  supporting_evidence: []
  contrary_evidence: []
  unknowns: []
  confidence: "unknown"
  invalidation_conditions: []
  next_review_at: "unknown"
```

[资产层](/asset-layer/)可以用共同环境和功能需求复核资产角色，但不能让短期宏观状态改写长期功能。[产品风险预算层](/product-risk-budget-layer/)只能在共同边界内形成某款产品的风险约束，不能反向修改宏观判断。

## 11. 模块明确不能做什么

宏观层不能：

- 选择代表指数、基金或具体 ETF；
- 决定某类资产应该占优、增配或减配；
- 生成任何产品的最终权重、目标波动或仓位；
- 产生买入、卖出、加仓、减仓、清仓、暂停或恢复动作；
- 根据一个指标或一条新闻直接改变共同风险边界；
- 在来源、口径、版本和可得时间未核验时输出确定结论；
- 用旧文章中的评分、阈值、比例或资产结论补齐当前规则；
- 用未来发布或修正的数据改写当时判断。

宏观风险边界与执行状态必须分开：

```text
宏观层：开放 / 中性 / 收敛 / 防守
执行层：正常 / 谨慎 / 暂停
```

“暂停调整”“冻结执行”和“恢复执行”只属于执行层（含风险闸门）。

## 12. 判断失效和复查条件

状态卡必须在写下判断时同时写下失效条件。失效条件应指向能够被观察的新事实，而不是“市场没有按预期运行”。

复查由两类条件触发：预定复查日期，或能够改变模块状态、共同风险边界、证据质量的事件。复查可以得到“保持原判断”，不要求每次产生变化。发现职责冲突或规则问题时，进入[系统运转与优化闭环](/system-loop/)的问题记录，不在正文里临时改规则。

## 13. 当前待验证事项

- 六个模块各自的最小指标集、精确口径和权威来源；
- 发布时点、修正版本和节假日延迟怎样写入 `available_at`；
- 模块状态和变化方向的统一词表；
- 非数字置信度的表达尺度；
- 六模块分歧、缺失和未知状态怎样形成共同边界；
- 边界切换需要保留哪些历史证据和人工评审记录；
- 合作伙伴能否在没有作者解释时区分宏观风险边界与交易动作。

当前完成的是职责、记录字段和输出契约，不是实时宏观状态，也不证明这套方法已经有效。
