## 系统不是一组静态规则

蜗牛全天候不仅要说明“当前怎样判断”，还要说明“判断错在哪里时，系统怎样知道，又怎样避免随意改规则”。完整运行路径是：

```text
可核验事实与数据
  → 宏观层的环境判断与不确定性
  → 资产角色与市场状态
  → 产品风险预算边界
  → 执行层的模拟调整或保持不动
  → 保存证据、假设和失效条件
  → 到期复查判断与结果
  → 发现并分类问题
  → 提出一项可验证修改
  → 验证、保留、继续观察或回滚
```

这条路径的前半段承接[投资方法论总纲](/design/)六层系统的输出，后半段进入跨层治理；其中单次决定与结果复查由[复盘层](/review-layer/)负责，规则实验和系统修改由本页负责。每个箭头都需要有输入和输出，不能依靠事后叙述补齐。

## 一次运行留下什么

| 环节 | 必须留下的内容 |
|---|---|
| 事实输入 | 数据名称、所属时间、当时真实可得时间、来源、缺失或修订状态 |
| 宏观判断 | 六个模块的状态、变化方向、支持证据、反对证据、未知项、置信度与失效条件 |
| 资产与信号 | 资产桶角色、趋势、相对强弱、波动与回撤风险，以及无法判断的状态 |
| 产品约束 | 中波产品当期允许的风险边界、资产桶限制、是否允许增加风险 |
| 执行结果 | 正常、谨慎或暂停；模拟调整或保持不动；风险闸门与恢复条件 |
| 复查计划 | 下次复查日期、需要回答的问题、哪些条件会否定原假设 |
| 后续复盘 | 实际结果、过程是否遵守、问题分类、是否需要修改系统 |

## 问题怎样被发现

问题可以从以下入口进入系统：

- 数据缺失、过期、修订、来源冲突或当时不可得；
- 主要证据与反对证据长期不一致；
- 宏观判断无法解释后续资产状态；
- 信号或产品约束突破上游边界；
- 中波产品的模拟动作违反既定风险纪律；
- 原判断的失效条件已经发生；
- 同类错误在多次复盘中重复出现；
- 合作伙伴对同一术语、规则或页面形成不同理解。

发现问题只代表需要调查，不代表系统一定要改。一次不利结果可能仍属于规则预期内的市场随机波动。

## 六类问题必须分开

| 分类 | 判断问题 | 首先处理什么 |
|---|---|---|
| 数据问题 | 输入是否缺失、滞后、修订、口径错误或当时不可得？ | 修复数据契约、来源和缺失状态，不先改投资规则 |
| 判断问题 | 当时是否错误解释证据、忽略反证或超出信息边界？ | 修订判断过程、证据要求或置信度表达 |
| 规则问题 | 规则是否在明确情景下反复失效？ | 提出一个有限修改，并重新验证 |
| 执行问题 | 正确规则是否没有被遵守？ | 修复检查、权限、流程或记录要求 |
| 表达问题 | 读者是否无法形成一致理解？ | 改写术语、结构、示例或链接 |
| 市场随机波动 | 结果是否不利，但过程和规则仍在预期范围内？ | 保持规则，继续观察，不制造修改 |

## 强制停顿：不能直接改参数

系统禁止下面这条捷径：

```text
结果不好 → 修改参数
```

正确路径是：

```text
发现异常
  → 保存当时证据
  → 选择一种问题分类
  → 判断是否真的需要改系统
  → 只提出一项修改
  → 预先写出验证和回滚条件
```

如果无法完成问题分类，当前决定只能是“继续观察”，不能用参数修改掩盖原因不明。

## 系统修改记录

任何方法论、产品规则或流程修改，都必须单独记录：

- 原问题；
- 支持证据；
- 问题分类；
- 准备修改的唯一规则或结构；
- 修改假设；
- 可能引入的新风险；
- 验证方法；
- 观察期限；
- 保留条件；
- 回滚条件；
- 修改前版本和修改后版本；
- 人工评审结果。

未验证的修改必须标记为“实验”，不能被描述成已经生效的现行规则。

## 四种处理结果

| 结果 | 适用条件 | 后续动作 |
|---|---|---|
| 保留 | 证据支持修改解决了原问题，且新风险在可接受范围 | 记录生效版本和理由 |
| 继续观察 | 样本不足、证据冲突或观察期限未结束 | 不改变现行规则，保留复查日期 |
| 回滚 | 修改未解决问题、引入更大风险或破坏上游边界 | 恢复旧版本并记录失败原因 |
| 不修改 | 问题属于执行、表达、数据或随机波动，而非规则失效 | 修复对应环节或保持原规则 |

## 当前采用的最小工具

当前只使用 Markdown、Git 版本记录和[系统决策记录](/decision-log/)保存变化。暂不建设实验平台、自动调参、回测系统、VPS 或周报自动化。

## 合作伙伴怎样参与

合作伙伴可以通过[阅读问题清单](/partner-review/)指出误解、反例和缺少证据的假设。反馈进入系统后，也必须经历“记录—分类—决定—修订—再阅读”，不会因为意见来自合作伙伴就直接变成规则。

> 本页描述的是系统治理方法，不代表任何投资规则已经通过历史或前向验证。
