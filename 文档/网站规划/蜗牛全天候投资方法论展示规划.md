## 1. 本次范围决定

蜗牛全天候网站当前的首要目的不是自动发布投资周报，也不是展示一个已经运行的量化系统，而是：

> 让合作伙伴完整理解我们的投资方法论，看清整个系统怎样从发现问题走到形成判断、产品约束、复盘和优化，并能够基于同一套结构提出问题、补充证据和参与迭代。

当前网站只围绕三条主线建设：

1. **投资方法论**：解释我们怎样认识环境、资产、风险和决策。
2. **系统运转与进化**：解释问题怎样暴露、怎样归因、怎样修改规则并验证优化。
3. **产品原型**：正式定义中波母产品概念，低波和高波只保留风险预算派生原则。

每周报告和 VPS 自动发布是方法论稳定后的运行能力，不属于当前最小范围。

## 2. 第一读者：合作伙伴

### 2.1 合作伙伴看完后应理解

1. 蜗牛全天候解决什么投资问题；
2. 我们怎样从宏观环境走到产品风险预算；
3. 宏观、资产、信号、产品、执行和复盘各自负责什么；
4. 一次判断怎样留下记录并进入后续复盘；
5. 系统怎样发现数据、判断、规则、执行和表达问题；
6. 一项优化怎样被提出、验证、保留或回滚；
7. 低波、中波、高波为什么共享一套方法；
8. 哪些内容已经确定，哪些仍是设计假设；
9. 当前最需要合作伙伴讨论和挑战的问题是什么。

### 2.2 合作伙伴不应产生的误解

- 网站不是荐股或择时信号服务；
- 中波概念以及低波、高波命名都不是已经可以购买的金融产品；
- 页面中的框架不代表已经完成历史或前向验证；
- 尚未确定的权重、阈值、收益和回撤不能由示例代替；
- 合作讨论不等于真实资金授权或交易建议。

## 3. 网站的一句话定位

建议使用下列方向作为首页核心表达，最终文案仍待确认：

> 蜗牛全天候是一套可解释、可约束、可复盘、可持续优化的资产配置系统。我们用它理解市场环境、设计不同风险预算的产品，并在发现问题后有纪律地改进系统。

辅助表达：

- 不追求预测每一次涨跌，先建立能够长期重复的判断过程；
- 不用单一观点决定仓位，让每一层只承担自己的职责；
- 不把回测包装成承诺，用证据、边界和复盘推动规则进化；
- 不因一次结果随意改规则，让每次优化都有问题记录、修改假设和验证结果。

## 4. 当前目标与非目标

### 4.1 当前目标

- 形成一套合作伙伴可以独立阅读的方法论总纲；
- 把六层投资流程的输入、输出和越界规则讲清楚；
- 展示系统从观察、判断、产品约束到复盘的完整运行路径；
- 定义问题发现、问题分类、优化验证和版本回退机制；
- 先完成宏观环境层的结构设计；
- 说明六个资产桶及其功能角色；
- 定义中波母产品概念，低波和高波只保留派生原则；
- 公开产品当前成熟度和未验证事项；
- 建立合作伙伴反馈、决定和版本修订机制；
- 让网站成为讨论的共同底稿，而不是单向宣传页。

### 4.2 当前明确不做

- 不建设 VPS 定时任务；
- 不自动生成或发布周报；
- 不接入完整宏观和行情数据源；
- 不展示未经验证的实时产品状态；
- 不公布固定产品权重、收益目标或回撤承诺；
- 不接实盘账户、券商接口或自动下单；
- 不恢复全部旧文章；
- 不用 AI 补造数字、引用或研究结论；
- 不以访问量、内容数量或自动化程度作为当前成功标准。

## 6. 首页规划

首页负责建立认知，不承担完整方法论正文。

### 6.1 首屏

- 品牌名称：蜗牛全天候；
- 一句话方法论定位；
- 当前状态：方法论设计与合作评审阶段；
- 主入口：阅读投资方法论；
- 次入口：查看产品原型。

### 6.2 方法论闭环

用一条清楚的路径展示：

```text
宏观环境
  → 资产角色
  → 市场信号
  → 产品风险预算
  → 执行与风险
  → 决策复盘
```

每一层只展示职责、输出和不能越过的边界。

### 6.3 中波母产品与派生原则

首页先展示一张中波母产品概念卡：

- 产品名称；
- 一句话定位；
- 相对风险预算；
- 当前成熟度；
- 尚未确定的关键事项；
- 产品详情入口；
- 低波和高波从中波收紧或放宽风险预算的简要说明。

### 6.4 系统怎样运转和进化

首页用一张小型闭环图说明：

```text
观察事实 → 形成判断 → 约束产品 → 记录过程 → 复查结果
    ↑                                             ↓
    └──── 发现问题 ← 分类归因 ← 验证修改 ← 提出优化 ────┘
```

这一部分要让合作伙伴看见：蜗牛全天候不是一组静态规则，而是一套保留证据、允许质疑、能够回滚的学习系统。

### 6.5 当前合作议题

首页设置“当前正在讨论什么”，只保留一到三个问题，例如：

- 宏观环境层应该怎样表达状态与不确定性；
- 中波母产品怎样定义基础风险预算；
- 低波和高波怎样只从中波派生，而不形成独立系统。

这个区域用于引导合作伙伴参与，而不是展示虚假的开发进度。

### 6.6 固定边界

首页和产品页持续显示：研究与模拟、不构成投资建议、没有实盘连接、不承诺收益。

## 7. 投资方法论总纲

方法论总纲需要先回答六个问题：

1. 当前环境是什么；
2. 哪些资产承担什么角色；
3. 哪些市场信号值得观察；
4. 产品允许承担多少风险；
5. 什么时候调整、什么时候保持不动；
6. 怎样判断原来的判断和规则是否有效。

六层之间遵循单向边界：

```text
上一层提供约束
下一层在约束内工作
任何一层都不能直接跳到交易动作
```

### 7.1 宏观环境层

负责输出共同环境和风险预算上限，不选择具体产品。

建议包含：

- 增长；
- 通胀与价格；
- 流动性与信用；
- 政策；
- 全球外部环境；
- 事件风险。

每个模块统一记录：

- 当前状态；
- 变化方向；
- 数据截止时间；
- 主要证据；
- 反对证据；
- 未知项；
- 置信度；
- 失效条件；
- 下次复查日期。

宏观层的最终输出不是买卖信号，而是“开放、中性、收敛、防守”四档共同风险边界。暂停或冻结执行只属于执行与风险层。

### 7.2 资产角色层

第一阶段只讨论六个资产桶：

- 现金；
- 债券；
- 红利；
- 宽基；
- 成长主题；
- 黄金。

每个资产桶说明核心功能、适用环境、主要风险、观察变量和产品使用边界。代表指数和具体 ETF 暂不确定。

### 7.3 市场信号层

第一阶段只保留：

- 趋势；
- 相对强弱；
- 波动与回撤风险。

信号用于描述资产桶状态，不能突破宏观风险上限，也不能直接下单。

### 7.4 产品风险预算层

当前先把共同环境和资产状态映射成中波母产品约束。低波和高波未来只从中波收紧或放宽风险预算，不另建宏观判断。

### 7.5 执行与风险层

说明检查频率、模拟调整、保持不动、风险闸门和恢复条件。第一阶段不连接真实账户。

### 7.6 决策复盘层

保存当时事实、判断、假设、失效条件、执行结果与后续归因，区分判断错误、规则错误、执行错误和市场随机性。

### 7.7 系统运转闭环

完整系统按下面的顺序工作：

```text
可核验事实与数据
  → 宏观环境与不确定性
  → 资产角色与市场状态
  → 产品风险预算边界
  → 模拟调整或保持不动
  → 保存证据、假设和失效条件
  → 到期复查判断与结果
  → 识别问题并分类
  → 提出一项可验证修改
  → 验证、保留、回滚或继续观察
```

系统不能从“出现问题”直接跳到“修改参数”。先归因，再决定是否需要改变系统。

### 7.8 问题怎样被发现

问题入口包括：

- 数据缺失、过期、修订或来源互相冲突；
- 支持证据和反对证据长期不一致；
- 宏观判断不能解释后续资产状态；
- 信号突破上层风险边界；
- 低波、中波、高波出现风险顺序倒挂；
- 模拟动作违反既定规则；
- 原判断的失效条件已经发生；
- 同类错误在多次复盘中重复出现；
- 合作伙伴无法理解页面，或对同一规则产生不同解释。

问题被发现不等于系统一定要修改。市场随机波动和单次结果也可能不构成规则问题。

### 7.9 问题分类

| 问题类型 | 核心问题 | 常见处理 |
|---|---|---|
| 数据问题 | 输入是否缺失、滞后、修订或口径错误？ | 修复数据契约和来源，不先改投资规则 |
| 判断问题 | 证据是否被错误解释或忽略反证？ | 修订判断过程和证据要求 |
| 规则问题 | 规则是否在明确情景下失效？ | 提出有限修改并重新验证 |
| 执行问题 | 正确规则是否没有被遵守？ | 修复流程、权限或检查清单 |
| 表达问题 | 合作伙伴是否无法得到一致理解？ | 改写术语、示例和页面结构 |
| 随机波动 | 结果是否只是不利但仍在规则预期内？ | 保持规则，继续观察 |

### 7.10 系统怎样优化

每项优化都必须包含：

- 原问题和证据；
- 问题分类；
- 准备修改的单一规则或结构；
- 为什么预计它能解决问题；
- 可能引入的新风险；
- 验证方法和观察期限；
- 保留、继续观察或回滚的条件；
- 修改前后版本与系统决策记录。

优化遵循以下纪律：

- 一次只解决一个清楚的问题；
- 不因一次盈亏修改规则；
- 不用未来数据解释过去决策；
- 不覆盖旧版本和旧判断；
- 修改方法论或产品规则必须人工评审；
- 没有验证结果的改动只能标记为实验。

## 8. 产品原型规划

### 8.1 产品关系

中波是当前唯一正式定义的母产品概念。低波和高波只保留派生原则，不是三套独立策略。

| 产品原型 | 初步定位 | 相对风险预算 | 当前状态 |
|---|---|---:|---|
| 蜗牛全天候·低波 | 从中波收紧风险预算 | 低于中波 | 仅保留派生原则 |
| 蜗牛全天候·中波 | 当前母产品概念 | 居中 | 概念定义阶段 |
| 蜗牛全天候·高波 | 从中波放宽风险预算 | 高于中波 | 仅保留派生原则 |

“高波”只表示未来允许在中波基础上放宽风险预算，不表示永远保持高仓位；共同宏观边界和风险闸门对所有派生版本同时生效。

### 8.2 定义顺序

定义顺序：

1. 定义中波母产品；
2. 完成中波规则草案所需证据；
3. 本轮只记录低波收紧、高波放宽的派生原则；
4. 中波通过后再单独决定是否展开派生产品。

### 8.3 标准产品卡

中波概念卡统一说明：

- 产品目标；
- 适合怎样的风险偏好和资金期限；
- 使用的资产桶；
- 基础风险预算；
- 资产上下限；
- 宏观环境映射；
- 风险闸门与恢复条件；
- 调整频率；
- 基准与比较口径；
- 当前成熟度；
- 未验证事项；
- 版本与变更记录。

没有数据依据的字段保持未定，不使用示例数字填满页面。

### 8.4 产品成熟度

```text
概念定义 → 规则草案 → 历史模拟 → 前向观察 → 稳定公开
```

当前只承诺推进到“概念定义”和“规则草案”。进入后续阶段需要新的数据、验证和范围决定。

## 9. 当前最小闭环

当前最小闭环不是自动周报，而是合作伙伴理解与反馈闭环：

```text
写出一章方法论和对应的系统运行路径
  → 发布为可阅读页面
  → 合作伙伴独立阅读
  → 收集误解、系统问题和反例
  → 对问题进行分类归因
  → 记录系统决定
  → 提出一项可验证的修订
  → 再次交给合作伙伴验证
```

### 9.1 第一轮建议范围

- 一份方法论总纲；
- 一章宏观环境层；
- 一张端到端系统运转与优化闭环图；
- 一份中波母产品概念卡；
- 一份合作伙伴阅读问题清单；
- 一次反馈与修订记录。

### 9.2 合作伙伴阅读问题

第一轮至少验证：

1. 能否用自己的话解释蜗牛全天候；
2. 能否分清六层职责；
3. 是否误以为宏观层直接决定交易；
4. 是否理解低波和高波只能从中波派生并共享同一方法；
5. 哪些假设缺少证据或存在反例；
6. 能否说清一个问题怎样从发现走到修改或保持不变；
7. 哪些术语对非作者不清楚；
8. 是否能指出当前仍未实现的能力。

### 9.3 最小闭环验收

- 合作伙伴不依赖作者口头解释也能读懂主线；
- 合作伙伴能指出至少一个需要澄清或挑战的假设；
- 反馈被记录为保留、修改、拒绝或待验证；
- 每个问题能被归入数据、判断、规则、执行、表达或随机波动；
- 重要修改进入系统决策记录；
- 页面修订后不存在旧版本和新版本互相矛盾；
- 未验证内容没有被包装成现行产品能力。

- `文档/组合构建/全天候引擎.md`：提取风险预算、再平衡和审计原则；
- `文档/风险管理/风险闸门.md`：作为执行与风险层素材；
- `文档/决策日志/决策日志模板.md`：作为合作反馈和方法修订的记录基础。

### 10.2 不能直接升级为现行规则

- 旧文章中的具体比例和投资结论；
- 没有来源、时点和版本的指标阈值；
- `fund_bot` 中固定的宏观占位状态；
- 私募申购、赎回信号和固定评分；
- 未测试或未纳入版本控制的回测；
- 历史长期路线图中的时间和 Alpha 扩展承诺。

### 10.3 旧公开内容

旧文章继续隐藏但不删除。只有当内容能够服务某一方法论章节、数据和引用重新核验、且不会被误读为现行建议时，才逐篇恢复或吸收。

## 11. 当前实施工作包

### S0：规划与信息架构确认｜当前

**交付物**：本规划、导航结构、方法论章节、产品关系与最小反馈闭环。

**退出条件**：合作伙伴是第一读者这一定位获得确认；周报和 VPS 明确退出当前范围。

### S1：方法论总纲

**交付物**：六层方法论总览、层级边界、共同术语、系统运行与优化闭环和阅读顺序。

**退出条件**：不依赖产品参数也能完整说明投资流程；各层不存在职责重叠；一个问题从发现到处理的路径清楚。

### S2：宏观环境层

**交付物**：六个宏观模块、统一状态卡、风险边界输出和未验证问题。

**退出条件**：宏观输出能够约束风险，但不会直接生成产品权重或交易动作。

### S3：资产、信号、执行与复盘

**交付物**：六个资产桶、三类信号、执行纪律、风险闸门和复盘模板。

**退出条件**：每个模块输入输出明确；信号和风控不会越权。

### S4：中波母产品概念

**交付物**：中波母产品概念卡，以及低波收紧、高波放宽的两条派生原则。

**退出条件**：中波怎样承接共同方法已经清楚；低波和高波没有被展开为独立规则或页面；所有具体数字都有依据或保持未定。

### S5：网站重组

**交付物**：新首页、主导航、方法论入口、产品原型入口和辅助页面关系。

**退出条件**：桌面端和移动端可读；旧内容不干扰；网站不暗示产品已经运行。

### S6：合作伙伴阅读与修订

**交付物**：阅读问题、问题分类、反馈记录、系统决定和第一轮可验证修订。

**退出条件**：合作伙伴可以独立解释方法论和系统运行；主要误解与问题有明确分类和处理结果。

## 12. 当前验收标准

- 网站明确以投资方法论展示为首要目标；
- 合作伙伴是第一读者；
- 首页能够引导读者进入方法论和产品原型；
- 方法论六层职责明确且不越权；
- 合作伙伴能够理解系统如何运行、发现问题和验证优化；
- 问题不会未经分类就直接变成参数修改；
- 当前只正式定义中波母产品概念；
- 低波和高波只保留派生原则，没有展开为三套系统；
- 中波显示成熟度和未验证事项；
- 未验证参数保持未定；
- 旧文章继续隐藏，不抢占方法论主线；
- 网站不提供投资建议、收益承诺或真实交易能力；
- 当前范围不包含周报、VPS 或自动化发布。
